Sheets become screens

Sheetsmith looks at each sheet and picks a screen for it:

  • List + form for each table. The first text column is the card title on phones; a dropdown column called Status, Stage or State becomes the filter chips.
  • Form when a sheet has labels next to input cells (unlocked cells, cells with validation, or values next to "Label:"). Formula cells next to labels become the results.
  • Results when a sheet only has labels next to formulas: a summary with big numbers.
  • Sheet for everything else: the cells as they are.

Hidden sheets and sheets that only feed dropdowns (often called Lists or Lookups) start hidden: they still work behind the scenes. In the studio's Screens tab you can rename, reorder and hide screens, pick icons, and change how each column shows (text, money, date, yes/no, choice…).

Formulas

Also: A1 and table references ([@Qty], Orders[Total], Orders[[#Totals],[Qty]]), named ranges, cross-sheet references, whole columns (A:A), array constants, and VBA Functions from the workbook. FILTER, SORT and UNIQUE give their first value (no spilling yet). A function that isn't on the list shows #NAME?; the studio lists any your workbook uses.

VBA macros

Sheetsmith reads the VBA project out of .xlsm files and runs it in the app with its own VBA interpreter. Buttons run their macros; MsgBox and InputBox show as dialogs.

What doesn't run

  • Files and folders (Open, Print #, Kill, Dir), and other programs (Shell, Outlook, Word, CreateObject other than Scripting.Dictionary). A web page can't reach them.
  • Windows API calls (Declare), class modules and UserForms.
  • Charts, shapes, pivot tables and printing from code.
  • Events about selecting, double-clicking, saving and closing.

A macro that runs too long (an endless loop) is stopped, with a message. Changes a macro made before an error are kept, like in Excel.

Run it on a network

  1. Pick the computer that shares the app. Any Windows PC, Mac, Linux box or Raspberry Pi that stays on while people work. It needs Python 3.8 or newer: free from python.org (tick "Add python.exe to PATH" on Windows). Macs and Linux usually have it.
  2. Unzip the download there and double-click Start (Windows).bat or start.command (Mac), or run python3 server.py.
  3. Open the address it prints, like http://192.168.1.20:8080, on every phone, tablet and computer on the same Wi-Fi. On phones, "Add to Home Screen" makes it open like an app.
python3 server.py --port 9000 another port python3 server.py --pin 4821 ask for a PIN first python3 server.py --reset start over with the workbook's data (keeps a backup)

It doesn't open on my phone. Check the phone is on the same Wi-Fi (not mobile data or a guest network), and that the computer's firewall lets Python accept connections on private networks (Windows asks the first time). Office networks sometimes block devices from talking to each other; ask whoever runs the network.

Updating the app. Change it in Sheetsmith, download again, and replace index.html and server.py. Keep the data folder: your data stays. New tables are added; existing rows are kept.

Keeping it running. Leave the window open, or start it when the computer starts (Task Scheduler on Windows, a login item on Mac, a systemd service or cron @reboot on Linux).

Limits & privacy

  • Workbooks up to 12 MB; up to 3,000 rows and 100 columns per sheet, and 40,000 cells in all, are read.
  • Old .xls files: open them in Excel and save as .xlsm first.
  • Trying Sheetsmith without an account: the workbook is read and set aside, nothing is kept. Saved projects keep the workbook in your account until you delete them.
  • The app you download is yours: it runs on your computers, its data stays there, and it never calls Sheetsmith or anyone else.
